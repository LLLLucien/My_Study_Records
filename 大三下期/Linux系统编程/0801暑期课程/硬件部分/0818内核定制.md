## 一、Linux 内核定制

### 1.1 内核源码获取

- ✅ 官方下载地址：<www.kernel.org>
- ✅ 老师课堂使用的是 `linux-source-5.0.0`（Ubuntu 源码包，解压后位于 `/usr/src/linux-source-5.0.0/`）

### 1.2 内核源码目录结构

> 设计思想：**将功能相关的文件组织在相同的目录**（树形结构），每个目录各司其职。

| 目录                                                          | 作用                                                                                                                        |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| arch                                                          | ✅ 根据 CPU 体系结构不同而区分的代码（如 x86_64、arm64 各自一套）                                                           |
| crypto                                                        | ✅ 加密、压缩、CRC 校验算法                                                                                                 |
| Documentation                                                 | ✅ 内核文档                                                                                                                 |
| drivers                                                       | ✅ 设备驱动程序源代码；**自己定制的设备驱动可以放到该目录的特定分类中**，随操作系统一起编译                                 |
| fs                                                            | ✅ 和文件系统有关的源代码                                                                                                   |
| include                                                       | ✅ 内核所需的头文件；实现驱动程序时使用的就是该目录下的头文件（**不能使用 C 库**），与平台无关的头文件在 `include/linux` 下 |
| init                                                          | 内核初始化代码                                                                                                              |
| ipc                                                           | 进程间通信（IPC）的实现                                                                                                     |
| kernel                                                        | ✅ Linux 内核核心部分代码（完成操作系统核心功能）                                                                           |
| lib                                                           | ✅ 库文件相关代码（**与平台相关**）                                                                                         |
| mm                                                            | ✅ 实现内存管理的源代码；与硬件体系结构无关的部分在这里（**与硬件相关的部分在 arch/xxx/mm/ 下**）                           |
| net                                                           | ✅ 网络协议栈                                                                                                               |
| scripts                                                       | ✅ 配置内核的脚本                                                                                                           |
| usr                                                           | ✅ 与用户相关的文件；`gen_init_cpio.c` 是 cpio 命令的实现（制作根文件系统的命令，将根文件系统和内核组织在一起）             |
| block / certs / firmware / security / sound / tools / virt 等 | 其他子系统：块设备、签名证书、固件、安全、声音、工具、虚拟化                                                                |

> 补充：老师 `ls` 看到的一级目录比上表更多（如 `Kbuild`、`MAINTAINERS`、`Module.symvers`、`vmlinux-gdb.py` 等），上表是核心功能目录。`Documentation` 在源码里有时写作 `Document`。

### 1.3 内核配置与编译机制

为了简化内核源代码的编译，内核采用 **三个文件协同** 的机制：

| 文件         | 作用                                                                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Makefile** | ✅ 根据配置情况，构造出需要编译的源文件列表，然后分别编译，并将目标代码链接到一起，最终形成 Linux 内核的二进制文件。因为源码按功能组织成树形结构，所以 **Makefile 分布在各个目录中**，具有完整的依赖链 |
| **Kconfig**  | ✅ 为用户提供**层次化的配置选项集**。执行 `make menuconfig` 时，通过分布在各个子目录中的 Kconfig 文件构建配置界面                                                                                      |
| **.config**  | ✅ 内核配置的结果。用户配置完成后，所有配置信息保存到该文件                                                                                                                                            |

> 补充：三者关系可记为——**Kconfig 定义"有哪些选项"，menuconfig 展示并保存"当前值"，Makefile 决定"编译什么"**。改配置本质就是改 .config。

### 1.4 配置界面中的按键（y / m / n）

| 按键 | 含义                   | 产物                          |
| ---- | ---------------------- | ----------------------------- |
| `y`  | 编译进内核（built-in） | 直接编入 vmlinux 镜像         |
| `m`  | 编译成模块             | 生成 `.ko` 文件，需要时再加载 |
| `n`  | 不编译该功能           | 无                            |

### 1.5 编译流程

1. ✅ 解压内核源码，进入源码目录
2. ✅ 执行 `make menuconfig`
3. ✅ 根据需要配置内核编译选项（y/m/n）
4. ✅ 保存退出，生成配置文件 `.config`
5. ✅ 执行 `make -j4` 编译
6. ✅ 编译完成生成 **bzImage**（内核映像文件）
   - 用 gcc 编译 → 可以在本机使用
   - 用交叉编译器编译 → 可以下载到开发板上使用

```bash
make -j4                # 编译内核镜像（-j4 表示 4 个并行任务）
make modules_install    # 安装模块（需要 sudo）
make install            # 安装内核
make clean              # 清理编译过程中生成的中间文件
make distclean          # 清理中间文件 + 配置文件（.config 等），恢复"干净"状态
```

> 补充：`make config` / `make xconfig` 也是配置方式（文本行 / 图形界面），课堂重点是 menuconfig。`make clean` 与 `make distclean` 的区别：前者只删产物，后者连配置一起删。

## 二、文件系统的定制

### 2.1 什么是文件系统

- ✅ 操作系统中负责管理和存储文件信息的软件机构称为**文件管理系统**，简称**文件系统**
- ✅ 文件系统由三部分组成：与文件管理有关的软件、被管理的文件、实施文件管理所需的数据结构
- ✅ 从系统角度看：文件系统是对文件存储器空间进行组织和分配，负责文件的存储，并对存入的文件进行保护和检索
- 具体职责：为用户建立文件、存入、读出、修改、转储文件、控制文件的存取，当用户不再使用时撤销文件

> 补充：这正好对应昨天（0817）笔记里嵌入式 Linux 的**第三棒**——内核启动后要挂载 rootfs，rootfs 就是一套完整的文件系统目录结构。

### 2.2 根文件系统的目录结构（FHS）

| 目录      | 作用                                                |
| --------- | --------------------------------------------------- |
| /bin      | ✅ 必备的用户命令                                   |
| /sbin     | ✅ 必备的系统管理员命令                             |
| /dev      | ✅ 设备文件                                         |
| /etc      | ✅ 系统配置文件，包括启动文件                       |
| /lib      | ✅ 必要的链接库（如 C 链接库、内核模块）            |
| /home     | ✅ 用户主目录                                       |
| /root     | ✅ root 用户主目录                                  |
| /usr      | ✅ 第二层：包含大多数用户都有用的大量应用程序和文件 |
| /usr/bin  | 非必备的用户程序                                    |
| /usr/sbin | 非必备的管理员程序                                  |
| /usr/lib  | 库文件                                              |
| /var      | ✅ 监控程序和工具程序所存放的可变数据               |
| /proc     | ✅ 提供内核与进程信息的虚拟文件系统                 |
| /mnt      | ✅ 文件系统挂接点，用于临时安装文件系统             |
| /tmp      | ✅ 暂时性的文件                                     |

### 2.3 init 进程启动系统的过程

- ✅ 代码在 busybox 的 `init/init.c` 中
- 初始化阶段：
  1. 设置信号处理函数
  2. 初始化控制台
  3. 解析 inittab
  4. 执行 inittab 命令（按动作类型分发）：
     - **SYSINIT**：系统初始化命令（如挂载文件系统）
     - **WAIT**：等待其执行完成的命令
     - **ONCE**：只执行一次的命令
     - **RESPAWN**：执行完退出后**重新启动**的命令（如登录 shell）
     - **ASKFIRST**：执行前先询问用户的命令
  5. 检测 RESPAWN 和 ASKFIRST 命令，有退出的则重新执行

> 补充：inittab 是 init 的"剧本"，每行格式为 `id:runlevel:action:command`，其中 **action 就是上面这些关键字**，告诉 init"这条命令什么时候、怎么执行"。

### 2.4 定制根文件系统的步骤

#### ① 建立根文件系统目录

```bash
mkdir rootfs
cd rootfs
mkdir root dev etc boot tmp var sys proc lib mnt home
mkdir etc/init.d etc/rc.d etc/sysconfig
mkdir usr/sbin usr/bin usr/lib usr/modules
# 创建设备节点：c 表示字符设备，主次设备号分别为 (5,1) 和 (1,3)
mknod -m 600 dev/console c 5 1
mknod -m 600 dev/null c 1 3
mkdir mnt/etc mnt/jffs2 mnt/yaffs mnt/data mnt/temp
mkdir var/lib var/lock var/run var/tmp
chmod 1777 tmp      # 1777：所有用户可写，且只能删自己的文件（粘滞位）
chmod 1777 var/tmp
```

> 补充：`mknod` 是创建设备文件的命令，`c 5 1` 中的 `5` 是主设备号（console）、`1` 是次设备号。

#### ② 建立动态链接库

- ✅ 如果有开发板提供的现成库，直接拷贝
- ✅ 如果没有，逐一找出开发板运行环境需要的库
- ✅ 拷贝到新建的根文件系统目录 `lib` 内

#### ③ 交叉编译 Busybox

- ✅ Busybox 是一个遵循 **GPL v2 协议**的开源项目
- ✅ 编写过程中对文件大小做了优化，并考虑了系统资源有限（如内存）的情况
- ✅ 使用 Busybox 可以**自动生成**根文件系统所需的 `bin`、`sbin`、`usr` 目录和 `linuxrc` 文件

> 补充：这正是我们之前用 BusyBox 构建 rootfs 的原理——系统里只有 busybox 一个"真程序"，其他命令都是软链接。

#### ④ 建立 etc 目录下的配置文件

## 三、驱动程序开发

### 3.1 什么是驱动程序

- ✅ 驱动程序是存在于**应用程序和实际设备之间**的软件层，是**操作系统内核和机器硬件之间的接口**
- 主要完成以下功能：

| 功能                                                        | 本质                                 |
| ----------------------------------------------------------- | ------------------------------------ |
| ✅ 对设备进行初始化和释放                                   | 和操作系统的交互（操作系统识别设备） |
| ✅ 把数据从内核传送到硬件和从硬件读取数据                   | 设备和操作系统的数据交互             |
| ✅ 读取应用程序传送给设备文件的数据和回送应用程序请求的数据 | 设备文件和设备的交互                 |
| ✅ 检测和处理设备出现的错误                                 | 异常处理                             |

### 3.2 为什么需要驱动程序（关键）

> ✅ 由于 **MMU 的内存映射**以及对操作系统的保护，运行在**用户态**的应用程序一般**不能直接访问硬件的地址**，因此需要驱动程序作为应用程序和硬件之间的接口。

### 3.3 驱动程序的分类与访问方式

| 类型     | 管理方            | 用户空间访问方式     |
| -------- | ----------------- | -------------------- |
| 字符设备 | ✅ 由文件系统管理 | 通过**设备文件**访问 |
| 块设备   | ✅ 由文件系统管理 | 通过**设备文件**访问 |
| 网络设备 | ✅ 由协议栈管理   | 通过 **socket** 访问 |
| 其他设备 | —                 | —                    |

### 3.4 设备文件

- 设备文件的属性由**三部分**信息组成：
  1. 第一部分：文件类型，值为 `c`（字符设备）/ `b`（块设备）
  2. 第二部分：**主设备号**
  3. 第三部分：**次设备号**
- ✅ **设备类型 + 主设备号** 唯一确定设备文件的驱动程序及其界面；**次设备号**说明目标设备是同类设备中的第几个

### 3.5 sys 文件系统

- ✅ Sys 文件系统是 Linux 内核中设计较新的**虚拟的、基于内存的文件系统**
- 作用与 proc 类似：可以**查看和设定内核参数**
- 额外作用：为 **Linux 统一设备模型**作为管理之用
- ✅ 只有读和写两个接口，比较简单，不支持复杂的操作
- 挂接在 Linux 文件系统的 **/sys** 目录

```bash
$ cat /sys/power/state          # 查看系统支持的休眠模式
freeze standby mem disk
$ echo standby > /sys/power/state   # 控制进入休眠模式
```

> 补充：proc 侧重进程与内核运行信息，sysfs 侧重**设备与驱动的树形视图**，两者都是虚拟文件系统，不占磁盘。

### 3.6 printk 日志级别（8 级）

- ✅ 内核通过 `printk()` 输出的信息具有日志级别
- 级别通过在输出字符串前加带尖括号的整数控制，如 `printk("<6>Hello, world!\n")`
- ✅ 内核共提供 **8 种日志级别**，宏定义在 `linux/kernel.h` 中

| 宏           | 数字  | 含义                                             |
| ------------ | ----- | ------------------------------------------------ |
| KERN_EMERG   | `<0>` | system is unusable（系统不可用）                 |
| KERN_ALERT   | `<1>` | action must be taken immediately（必须立即处理） |
| KERN_CRIT    | `<2>` | critical conditions（严重情况）                  |
| KERN_ERR     | `<3>` | error conditions（错误情况）                     |
| KERN_WARNING | `<4>` | warning conditions（警告）                       |
| KERN_NOTICE  | `<5>` | normal but significant（正常但重要）             |
| KERN_INFO    | `<6>` | informational（提示信息）                        |
| KERN_DEBUG   | `<7>` | debug-level messages（调试信息）                 |

> 补充：数字越小级别越高（越紧急）。`dmesg` 默认显示级别不高于 console_loglevel 的日志；`KERN_ALERT`（<1>）基本必显示。

### 3.7 驱动模块的加载与卸载

- ✅ 编译生成 `.ko` 模块；使用时用 **insmod** 命令加载，卸载用 **rmmod**
- ✅ 使用 insmod 时，会调用代码中 `module_init()` 指定的函数；函数里的 printk 会打印到日志，用 **dmesg** 查看
- ✅ 使用 **lsmod** 查看当前系统中加载的驱动程序

### 3.8 驱动实验：TestDriver

#### 驱动源码 `TestDriver0818.c`

```c
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/types.h>
#include <linux/kernel.h>
#include <linux/module.h>

MODULE_LICENSE("Dual BSD/GPL");

// 设备初始化：完成设备硬件的初始化，并向操作系统注册该设备
static int test_init(void)
{
    // 设备硬件初始化
    // 设备的注册
    printk(KERN_ALERT "Hello, My first driver login\n");  // 内核中的输出函数
    return 0;
}

// 设备的注销：释放设备所占用的资源，从操作系统中注销设备
static void test_exit(void)
{
    // 设备所用资源的释放
    // 设备的注销
    printk(KERN_ALERT "Bye, My first driver exit\n");
}

module_init(test_init);
module_exit(test_exit);
```
