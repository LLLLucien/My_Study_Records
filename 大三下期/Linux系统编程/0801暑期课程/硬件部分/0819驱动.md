# 0819 字符设备驱动开发

> 本文按"先看目标 → 再看骨架 → 再读代码 → 跑通流程"的顺序讲解，所有代码都带逐行注释。一天的内容浓缩成一句话：**让应用程序能通过 `/dev` 下的文件，读写你的设备。**

---

## 〇、今天在做什么？—— 和昨天（0818）的区别

昨天你写的驱动只能"加载 / 卸载 + 打日志"，**应用程序根本碰不到它**：

```
昨天：insmod → 内核调 test_init → printk 打日志 → 完事（应用无感知）
今天：insmod → 应用 open/read/write "/dev/xxx" → 驱动干活 → 应用拿到数据 ✅
```

为了达成这个目标，今天比昨天多出 **3 件新东西**：

| 新增的东西 | 一句话作用 | 类比 |
|---|---|---|
| `struct file_operations` 接线表 | 把系统调用 `read/write` 和你的函数绑在一起 | 岗位合同 |
| `register_chrdev()` | 向内核登记"我这个设备存在，主设备号 238" | 去人事部报到 |
| `mknod` + 设备文件 | 在 `/dev` 下创建应用的入口文件 | 挂门牌 |

**完整链路预览**（今天的全部内容就是打通这条链）：

```
test 应用
  │  open("/dev/Test_Char_Dev_0819")        ← 必须先 mknod 建好这个文件
  ▼
VFS（内核"总机"）看设备文件上的门牌号 238，去台账查
  ▼
找到你的驱动 → 执行 myfops 接线表里的 read 函数
  ▼
copy_to_user 把内核变量 dev_value(=99) 搬给应用
  ▼
printf("n = 99")     ← 应用读到了内核里的数据
```

> 你昨天已经会的部分（写 .c → 改 Makefile → make → insmod → rmmod）今天照旧，**只多** mknod 和写应用测试程序这两件事。

## 一、先看全貌：驱动源码只有 5 个部分

写一个字符设备驱动，`.c` 文件从上到下固定 5 块（顺序不能乱，因为后面的块要引用前面的东西）：

```c
// ① 头文件：借内核自带的"说明书"（不是你自己定义的！）
#include <linux/module.h>   // module_init / module_exit / MODULE_LICENSE 等宏
#include <linux/kernel.h>   // printk
#include <linux/fs.h>       // struct file_operations 这个"类型"定义在这里
#include <linux/init.h>     // __init / __exit 标记
#include <linux/types.h>
#include <asm/uaccess.h>    // copy_to_user / copy_from_user 的声明

// ② 自己的数据：模拟一个"设备"
//    （真实驱动里这里是硬件寄存器 / 传感器读数，今天用个变量假装）
static int dev_value = 99;

// ③ IO 实现函数：真正干活的（应用 read/write 最终执行到这里）
ssize_t test_char_read(...)  { ... copy_to_user ... }
ssize_t test_char_write(...) { ... copy_from_user ... }

// ④ 接线表：声明"这个设备支持 read 和 write"
static struct file_operations myfops = { read: ..., write: ... };

// ⑤ 注册 / 注销：加载时向内核报到（登记主设备号），卸载时注销
static int __init myinit(void)  { register_chrdev(238, "...", &myfops); }
static void __exit myexit(void) { unregister_chrdev(238, "..."); }
module_init(myinit);   // 告诉内核：加载 .ko 时调用 myinit
module_exit(myexit);   // 告诉内核：卸载 .ko 时调用 myexit
```

**5 块的依赖关系是单向的**：⑤ 依赖 ④（register_chrdev 要把 `&myfops` 交出去）→ ④ 依赖 ③（表里成员指向函数）→ ③ 依赖 ②（函数读写 dev_value）。所以必须按 ①→⑤ 的顺序写，先有函数才能引用函数。

## 二、完整源码（逐行注释版）

```c
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>      // struct file_operations 类型定义
#include <linux/init.h>
#include <linux/types.h>
#include <asm/uaccess.h>   // raw_copy_to_user / raw_copy_from_user 声明

#define MAJOR_NUM 238      // 主设备号：应用通过它找到这个驱动

// 模拟设备数据：相当于真实驱动里的"硬件寄存器读数"
static int dev_value = 99;

MODULE_LICENSE("GPL");     // 声明开源协议（不声明 insmod 会报警告）

/**
 * @brief 读函数：应用执行 read(fd, buf, 4) 时被内核调用
 * @param fp  内核传进来的文件对象（打开设备文件得到的）
 * @param buf 用户空间缓冲区（应用传进来装数据用的）
 * @param len 期望读的字节数
 * @param t   文件读写位置（简单驱动用不到）
 * @retval 返回复制的字节数
 */
ssize_t test_char_read(struct file *fp, char __user *buf, size_t len, loff_t *t)
{
 // 把内核变量 dev_value 的 4 字节搬进用户空间的 buf
 int length = raw_copy_to_user(buf, &dev_value, 4);

 return length;   // 返回实际搬了多少字节
}

/**
 * @brief 写函数：应用执行 write(fd, buf, 4) 时被内核调用
 * @param buf 用户空间缓冲区（应用传进来要写的数据）
 */
ssize_t test_char_write(struct file *fp, const char __user *buf, size_t len, loff_t *t)
{
 // 把用户空间 buf 的 4 字节搬进内核变量 dev_value
 int length = raw_copy_from_user(&dev_value, buf, 4);

 return length;
}

// 接线表：内核"按表找人"的唯一依据
static struct file_operations myfops = {
 owner : THIS_MODULE,          // 表示模块正在使用，防止被误卸载
 read  : test_char_read,       // 应用 read  → 执行 test_char_read
 write : test_char_write,      // 应用 write → 执行 test_char_write
};

/**
 * @brief 初始化函数：insmod 加载时自动执行
 * @retval 0 成功；-1 注册失败
 */
static int __init myinit(void)
{
 // register_chrdev：向内核登记"主设备号 238 + 名字 + 接线表"
 // 返回 0 = 成功；非 0 = 失败（比如 238 已被别的驱动占用）
 if (register_chrdev(MAJOR_NUM, "Test_Char_Dev_0819", &myfops)) {
  printk("<4>Register Failed\n");    // 注册失败
  return -1;
 } else {
  printk("<4>Register Success\n");   // 注册成功
  return 0;
 }
}

/**
 * @brief 退出函数：rmmod 卸载时自动执行
 */
static void __exit myexit(void)
{
 printk("<4>Test_Char_Dev_0819 exit\n");
 unregister_chrdev(MAJOR_NUM, "Test_Char_Dev_0819");   // 归还设备号
}

module_init(myinit);   // 加载 .ko → 自动调 myinit
module_exit(myexit);   // 卸载 .ko → 自动调 myexit
```

### 两个必须搞懂的点

**① register_chrdev 是"报到"**

```c
register_chrdev(主设备号, 设备名字, 接线表地址)
```

- 返回值：`0` = 成功，非 0 = 失败（主设备号被占用等）
- 主设备号写 **0** = 让内核**动态分配**（装完要看 `/proc/devices` 才知道分到几号）；写 **238** 这种具体数字 = 静态注册

**② 为什么必须用 copy 函数搬数据，不能直接赋值？**

`dev_value` 在内核空间，`buf` 在用户空间。用户态进程用的是虚拟地址，而且**用户态禁止访问内核空间**（MMU 挡着，昨天学过）。所以只能靠内核提供的专用搬运函数：

| 函数 | 方向 | 作用 |
|---|---|---|
| `copy_to_user(用户buf, 内核变量, 长度)` | 内核 → 用户 | 把内核数据交给应用 |
| `copy_from_user(内核变量, 用户buf, 长度)` | 用户 → 内核 | 把应用数据收进内核 |

> ⚠️ **返回值语义（易错点）**：返回"**没复制成功的字节数**"——全部成功返回 `0`，失败返回剩余字节数。不是返回复制了多少字节！

> 老师示例用的是 `raw_copy_*_user`（不带安全检查，快但危险）；实际项目推荐用带安全检查的 `copy_to_user` / `copy_from_user`，用法完全一样。

## 三、把驱动跑起来：4 个命令

```bash
# ① 编译：Makefile 和昨天一样，只改一行 obj-m := Test_Char_Dev_0819.o
make                          # 产物：Test_Char_Dev_0819.ko

# ② 装进内核（触发 myinit → register_chrdev 登记 238）
sudo insmod ./Test_Char_Dev_0819.ko

# ③ 确认注册成功
sudo dmesg | tail -5          # 看到 Register Success
cat /proc/devices             # 看到一行：238 Test_Char_Dev_0819

# ④ 建入口：应用 open 的"门牌"（今天新增的一步！）
sudo mknod /dev/Test_Char_Dev_0819 c 238 0
```

### 为什么必须 mknod？—— insmod 和 mknod 是两件事

- `insmod` 只让**内核**"认识"238 号设备（台账里登记了）
- 但**应用**不会说"我要访问 238 号设备"，它只会 `open("/dev/xxx")`
- `mknod` 就是在 `/dev` 下挂一个写着"238"的门牌文件：应用 open 它 → VFS 看门牌号 → 去台账查 238 → 找到你的驱动

```
sudo mknod /dev/Test_Char_Dev_0819 c 238 0
            │                        │  │  │
            │                        │  │  └─ 0 = 次设备号
            │                        │  └──── 238 = 主设备号
            │                        └─────── c = 字符设备（b = 块设备）
            └────────────────────────────── 应用要 open 的文件名
```

> 一句话：**insmod 是给设备"办身份"（内核台账），mknod 是给应用"开门"（/dev 门牌），缺一个都通不了。** Windows 上这两步是自动完成的（自动装驱动 + udev 自动建节点），所以你平时感觉不到；老师让你手动敲，就是为了看清本质。

> `cat /proc/devices` 显示的是"已注册设备的主设备号 + 名字"（内核台账），**不代表设备文件已存在**——所以之后还要 mknod。

## 四、应用层测试：test.c（逐行注释版）

```c
#include <stdio.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>
#include <stdlib.h>
#include <fcntl.h>

int main(int argc, char *argv[])
{
 int fd;      // 文件描述符（open 的返回值，之后 read/close 都靠它）
 int n;       // 用来接收从设备读到的数据

 // 打开设备文件（应用访问设备的唯一入口）
 fd = open("/dev/Test_Char_Dev_0819", O_RDONLY);
 if (fd < 0) {          // open 失败（比如没 mknod → No such file or directory）
  perror("Open");       // 打印失败原因
  exit(-1);
 }

 // 从设备读 4 字节到 n —— 内核会调用驱动的 test_char_read
 read(fd, &n, 4);

 printf("n = %d\n", n); // 打印读到的值，应为 99（dev_value 的初始值）

 close(fd);             // 关闭设备
 return 0;
}
```

编译运行：

```bash
gcc test.c -o test
./test
# 输出：n = 99    ← 应用读到了内核空间 dev_value 的值，链路打通！✅
```

### 这次 read 的完整旅程（数据流）

```
./test 执行 read(fd, &n, 4)
  → 系统调用（用户态 → 内核态）
  → VFS 总机看 fd 对应设备文件的门牌号 238
  → 台账查 238 → 找到你的驱动 → 调 myfops.read = test_char_read
  → raw_copy_to_user(buf, &dev_value, 4)  把 99 从内核搬给用户
  → 返回用户态 → n = 99 → printf 打印
```

ssize_t test_char_write(struct file *fp, const char __user *buf, size_t len, loff_t *t)

 int length = raw_copy_from_user(&dev_value, buf, 4);

## 六、补充知识（了解即可，不要求掌握）

### 6.1 字符设备驱动的"三大部分"（老师的理论框架）

| 部分 | 干什么 | 对应代码 |
|---|---|---|
| 初始化子程序 | 检测硬件是否存在、初始化设备 | `myinit` |
| I/O 服务子程序（上半部） | 处理应用发来的读写请求 | `test_char_read` / `test_char_write` |
| 中断服务子程序（下半部） | 处理硬件产生的中断 | 今天没涉及 |

> 上半部 = 应用 open/read/write 进入内核后执行的路径，此时驱动"借"调用进程的上下文运行（用户态切到核心态，但归属仍是那个进程）；下半部 = 硬件产生中断时执行的处理，时机不确定，是异步的。

### 6.2 把自己写的驱动编进内核（编成 =y 而不是 .ko）

今天学的是"编译成 .ko 模块，运行时 insmod 插入"；还有一种方式是把驱动**直接编进 vmlinux**：

1. 把源码放进内核目录：`cp xxx.c /usr/src/linux-5.0/drivers/char/`
2. 修改该目录的 `Kconfig`：添加一个配置选项（menuconfig 里才会出现）
3. 修改该目录的 `Makefile`：加一行 `obj-$(CONFIG_XXX) += xxx.o`
4. `make menuconfig` 勾选 → `.config` 里出现新选项 → `make` 编进内核

> 理解要点：`.config` 里的选项 → Makefile 决定编不编这个 .o → 编进去就内建（=y）。这就是"配置内核"的本质。

### 6.3 块设备 & USB 设备驱动（下节课预告）

- **块设备**：有固定的块大小（如 512 字节）、支持随机读写（硬盘、U 盘）；对应结构体叫 `block_device_operations`
- **USB 设备**：内核源码 `drivers/usb/usb-skeleton.c` 是官方"骨架程序"，写 USB 驱动照着它改就行

## 总结：今天学的就是这 4 句话

1. **驱动源码 = 5 块**：头文件 → 数据 → IO 函数 → 接线表 → 注册/注销，从上到下写
2. **接线表 file_operations** 把系统调用和你的函数绑定，内核"按表找人"
3. **数据搬运必须用 copy_to_user / copy_from_user**（用户态碰不到内核空间）
4. **跑通流程 = insmod（办身份）→ mknod（挂门牌）→ ./test（应用读写）**
