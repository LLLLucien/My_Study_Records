## 三、ARM 体系架构：RISC vs CISC

### RISC（精简指令集计算机）

- ✅ 指令系统简单（约 100 条指令），寻址方式相对少（ARM 常用 8 种）
- ✅ 所有指令格式整齐（ARM 模式固定 32 位），每条指令执行行为基本一致，**便于流水线设计**
- ✅ 存储器与 CPU 之间的数据交互只通过 **Load/Store 指令**完成

> 补充：RISC 的 Load/Store 架构——运算指令只能操作寄存器，不能直接访问内存；想用内存中的数据必须先 `Load` 到寄存器，运算完再 `Store` 写回。代表：ARM、MIPS、RISC-V。

### CISC（复杂指令集计算机）

- ✅ 所有功能都有专用指令完成，指令复杂、长度不固定
- ✅ 一条指令可完成复杂操作（如直接对内存做运算）
- ✅ 代表：X86 架构

### 对比总结

| 对比项   | RISC               | CISC           |
| -------- | ------------------ | -------------- |
| 指令数量 | 少（约 100 条）    | 多             |
| 指令长度 | 固定               | 不固定         |
| 寻址方式 | 少                 | 多且复杂       |
| 访存方式 | 仅 Load/Store 访存 | 指令可直接访存 |
| 流水线   | 容易设计           | 较难           |
| 代表     | ARM、MIPS、RISC-V  | X86            |

## 四、计算机体系结构（冯诺依曼 vs 哈佛）

### 冯诺依曼体系结构

- ✅ 程序存储和数据存储采用**同一套总线**（同一存储器）
- 特点：存储程序概念，结构简单；但取指令和取数据不能同时进行（**冯诺依曼瓶颈**）
- 典型：ARM7 内核

### 哈佛体系结构

- ✅ 程序存储和数据存储**分开**，是独立的（独立存储空间 + 独立总线）
- 特点：可同时取指令和取数据，**吞吐率高**，适合流水线
- 典型：ARM9 及以后内核、DSP

> 补充：现代处理器多采用**改进型哈佛结构**（内部数据、指令 Cache 分离，外部统一内存）。

## 五、数据存储（数据类型与大小端）

### 数据类型（按 ARM 约定）

| 类型                 | 大小   | 说明  |
| -------------------- | ------ | ----- |
| 字节数据 Byte        | 1 byte | 8 位  |
| 半字数据 Half-word   | 2 byte | 16 位 |
| 字数据 Word          | 4 byte | 32 位 |
| 双字数据 Double-word | 8 byte | 64 位 |

### 大小端存储（多字节数据在内存中的存放顺序）

> 核心：地址编号小的叫**低地址**，编号大的叫**高地址**。变量起始地址 `&a` 就是最低地址。

✅ **小端存储（Little-Endian）**：低位字节存在低地址，高位字节存在高地址

```text
以 0x12345678 为例（0x78 是最低位，0x12 是最高位）：
低地址 →→→→→→→→→→→ 高地址
[ 0x78 ] [ 0x56 ] [ 0x34 ] [ 0x12 ]
```

✅ **大端存储（Big-Endian）**：高位字节存在低地址，低位字节存在高地址

```text
以 0x12345678 为例：
低地址 →→→→→→→→→→→ 高地址
[ 0x12 ] [ 0x34 ] [ 0x56 ] [ 0x78 ]
```

### 对比记忆

| 存储方式           | 低地址放的字节 | 内存中的样子  | 记忆口诀             |
| ------------------ | -------------- | ------------- | -------------------- |
| 大端 Big-Endian    | 最高位（大头） | `12 34 56 78` | 大头在前，像正常写字 |
| 小端 Little-Endian | 最低位（小头） | `78 56 34 12` | 小头在前，倒着写     |

> 补充：x86、ARM 默认小端；网络字节序规定为大端。代码中可通过指针按字节查看第一个字节判断当前机器的大小端。

## 六、ARM 处理器模式

### 7 种工作模式

| 模式         | 简称 | 类型   | 说明                                                                  |
| ------------ | ---- | ------ | --------------------------------------------------------------------- |
| 用户模式     | USR  | 非特权 | ✅ 用户程序运行在此模式；不能访问内核空间，也不能主动切换到其他模式   |
| 系统模式     | SYS  | 特权   | ✅ 运行特权级操作系统任务，可以切换到其他特权模式                     |
| 管理模式     | SVC  | 特权   | 复位、软中断（SWI）时进入，**操作系统内核模式**                       |
| 快速中断模式 | FIQ  | 特权   | 处理高优先级中断                                                      |
| 中断模式     | IRQ  | 特权   | 处理普通中断                                                          |
| 中止模式     | ABT  | 特权   | 指令预取/数据访问异常时进入（与虚拟内存和存储器保护相关）             |
| 未定义模式   | UND  | 特权   | 执行未定义指令时进入                                                  |

> 补充：
>
> - 除用户模式外，其余 6 种都是**特权模式**，特权模式之间可以自由切换。
> - **用户模式和系统模式都不能由异常而进入**，且二者拥有**完全相同的寄存器组**（见下一节）。
> - 模式切换主要通过**异常**完成：复位、SWI 软中断、IRQ/FIQ 硬件中断、未定义指令、中止异常。

### SVC 模式（管理模式）

- SVC = Supervisor，**CPU 的管理员账号**（特权模式之一）
- 操作系统内核运行在 SVC 模式，可访问所有内存、操作硬件寄存器
- 普通程序在**用户模式**，想干特权的事必须通过软中断指令（SVC/SWI）请求内核代做
- 复位后 CPU 自动进入 SVC 模式

### IRQ / FIQ（两种中断）

|            | IRQ                        | FIQ                              |
| ---------- | -------------------------- | -------------------------------- |
| 全称       | Interrupt Request 普通中断 | Fast Interrupt Request 快速中断  |
| 优先级     | 低                         | 高（可打断 IRQ 处理）            |
| 专用寄存器 | 无                         | 有 R8-R12 副本，不用压栈，响应快 |
| 用途       | 串口、定时器等常规外设     | 掉电保护、高速采样等紧急任务     |

- 启动阶段要**屏蔽 IRQ/FIQ**，防止初始化被打断

## 七、寄存器结构（ARM 寄存器）

### 寄存器总览

✅ ARM 处理器共有 **37 个寄存器**：**31 个 32 位通用寄存器 + 6 个状态寄存器（CPSR/SPSR）**。

通用寄存器按是否随模式变化分为两类：

- **未分组寄存器 R0-R7**：在所有模式下都是**同一个物理寄存器**，各模式共用
- **分组寄存器 R8-R14**：不同模式下对应**不同的物理寄存器**（各模式有独立备份），模式切换时硬件自动切到对应副本，不会互相覆盖

> 这样设计的目的：异常/中断发生时，CPU 直接切到新模式对应的"另一套寄存器"，不用先保存旧值就能立刻使用，响应更快。

### 通用寄存器 R0-R15

| 寄存器 | 名称          | 作用                                                                      |
| ------ | ------------- | ------------------------------------------------------------------------- |
| R0-R12 | 通用寄存器    | ✅ 一般用途，无特殊限定                                                   |
| R13    | SP 栈指针     | ✅ 存储栈顶地址                                                           |
| R14    | LR 链接寄存器 | ✅ 存储返回地址（执行 BL 调用指令时自动保存）                             |
| R15    | PC 程序计数器 | ✅ 指向**当前正在取指的指令地址**（流水线工作，通常比正在执行的指令超前） |

> 补充：
>
> - **R15 就是 PC**，程序跳转 = 修改 PC。
> - R13（SP）是栈指针，指向栈顶；R14（LR）保存返回地址（执行 `BL` 调用指令时自动写入）。
> - 各特权模式都有自己独立的 **SP、LR 副本**（Banked Registers），保证异常发生时不会破坏用户模式的栈与返回地址。

### 各模式的寄存器分布

| 模式         | 通用寄存器（R0-R15）                    | 状态寄存器       |
| ------------ | --------------------------------------- | ---------------- |
| 用户/系统    | R0-R15                                  | CPSR             |
| 管理模式     | R0-R12、R13_svc、R14_svc、R15           | CPSR、SPSR_svc   |
| 中止模式     | R0-R12、R13_abt、R14_abt、R15           | CPSR、SPSR_abt   |
| 未定义模式   | R0-R12、R13_und、R14_und、R15           | CPSR、SPSR_und   |
| 中断模式     | R0-R12、R13_irq、R14_irq、R15           | CPSR、SPSR_irq   |
| 快速中断模式 | R0-R7、R8_fiq ~ R14_fiq、R15            | CPSR、SPSR_fiq   |

> 规律：
>
> - 异常模式（SVC/ABT/UND/IRQ）各自有独立的 **R13、R14** 副本
> - **FIQ 拥有 R8-R14 全部 7 个副本**，现场几乎不用保存，所以响应最快
> - 每个特权模式各有一个 **SPSR**，用来保存进入异常前的 CPSR

### 状态寄存器 CPSR / SPSR

**CPSR（Current Program Status Register）**：✅ 当前程序状态寄存器，保存程序状态：处理器模式、中断屏蔽位、条件标志位等。

**SPSR（Saved Program Status Register）**：异常发生时用于**保存被中断模式的 CPSR**，返回时恢复。

### CPSR 中的标志位

✅ **N、Z、C、V** 为条件标志位：

| 标志位        | 含义          | 置位条件                     |
| ------------- | ------------- | ---------------------------- |
| N（Negative） | 负标志        | 运算结果为负数（最高位为 1） |
| Z（Zero）     | 零标志        | 运算结果为 0                 |
| C（Carry）    | 进位/借位标志 | 无符号运算产生进位（或借位） |
| V（oVerflow） | 溢出标志      | 有符号运算结果超出表示范围   |

### CPSR 的控制位（除条件标志位外）

- **M[4:0]（模式位，第 0-4 位）**：用于设置处理器工作模式
- **T 位（Thumb 状态位）**：指示当前指令集是 ARM（0）还是 Thumb（1）。注意：处理器工作模式的切换通过 `bx` 指令完成，**T 位只是只读指示**，不能通过写它来切换模式
- **F 位（快速中断禁止位）**：置 1 表示禁止 FIQ
- **I 位（中断禁止位）**：置 1 表示禁止 IRQ

## 八、上下文切换（Context Switch）

- ✅ 上下文（Context）：CPU 当前的执行环境，即**寄存器组的状态**
- ✅ 切换上下文需要保存：**PC（返回地址）、通用寄存器（R0-R12）、SP、CPSR** 等
- 中断/异常发生时的自动动作（硬件完成）：
  1. 将当前 CPSR 保存到 **SPSR**
  2. 将返回地址保存到 **LR**
  3. 切换到对应的异常模式
- 其余现场（通用寄存器等）由**软件（中断服务程序开头/结尾）保存与恢复**

> 这就是"进入中断要压栈、退出中断要弹栈"的原因——保护现场，才能返回原程序继续执行。

## 九、BootLoader 与内核启动

### BootLoader（引导程序）是什么

- 上电后**最先运行的代码**，相当于 **PC 机的 BIOS**，是操作系统运行之前执行的一段小程序
- 负责：初始化硬件设备、建立内存空间的映射表 → 把内核镜像从 Flash 拷到内存 → 设置 CPU 状态 → 跳转到内核
- 常见实现：**U-Boot**（Universal Boot Loader，通用引导程序，嵌入式 Linux 最常用的引导程序）

### U-Boot 与 u-boot.bin

**U-Boot**：引导程序的"具体产品"（BootLoader 是概念，U-Boot 是最常用的实现）。

**u-boot.bin**：U-Boot 源码经过**交叉编译**后生成的二进制机器码文件（.bin 即 binary，二进制），芯片可直接执行。

**交叉编译**：在 PC（x86）上编译出 ARM 架构芯片能跑的代码。

**烧录**：把 u-boot.bin 写入开发板的存储设备（SD 卡 / eMMC / SPI Flash / NAND），断电不丢，上电自动运行。

### 嵌入式 Linux 启动四级接力

| 阶段  | 谁         | 存在哪               | 作用                        |
| ----- | ---------- | -------------------- | --------------------------- |
| 第1棒 | BootROM    | 芯片内部（出厂固化） | 上电启动，找到并加载 U-Boot |
| 第2棒 | U-Boot     | SD卡/Flash           | 初始化硬件，加载内核        |
| 第3棒 | Linux 内核 | SD卡/Flash           | 管理系统                    |
| 第4棒 | 根文件系统 | SD卡/Flash           | 提供命令/程序（/bin、/etc） |

### 硬件初始化工作（BootLoader 上电后要做的事）

✅ 系统加电复位后，几乎所有的 CPU 都从**复位地址**开始取指令（BootLoader 就放在那里）。

1. **关闭处理器内部指令/数据 Cache**：保证初始化时读到的是"干净"的数据
2. **关闭中断**：初始化过程不能被中断打断
3. **关闭看门狗**：防止初始化耗时较长而被看门狗强制复位
4. **配置 PLL**：锁相环，设置 CPU 运行时钟
5. **配置内存**：初始化 SDRAM/DDR 控制器
6. **初始化各工作模式的堆栈**：为每种模式设置独立的 SP
7. **配置中断**：建立中断向量表
8. **拷贝 RW 段、初始化 ZI 段**：把可读写数据段搬入内存，把未初始化数据区清零

### 为什么内核启动要做准备工作

✅ 内核的启动需要内存映射在主存的适当位置，因此跳转前必须：

1. **CPU 寄存器设置**：设置栈指针 SP（汇编代码要用栈）、关键状态寄存器
2. **CPU 模式**：确认处于特权模式（复位后自动进 SVC 模式），才有权限操作硬件
3. **Cache 和 MMU 设置**：先关 MMU、清 Cache，保证交接给内核时状态"干净"（避免脏数据）

### MMU（内存管理单元）

- MMU = Memory Management Unit，干两件事：
  - **地址翻译**：虚拟地址 → 物理地址（Linux 每个进程有独立虚拟地址空间）
  - **权限保护**：检查内存访问权限，隔离进程
- BootLoader 早期**关 MMU**（直接用物理地址操作硬件）；内核启动后再开启并建立映射

### 完整启动流程

```text
上电复位
  │
  ▼
BootLoader：
  1. 设置 SP 栈，进入 SVC（特权）模式
  2. 关 MMU、清 Cache
  3. 屏蔽 IRQ/FIQ（启动过程不能被打断）
  4. 初始化内存、时钟、外设
  5. 把内核镜像拷贝到内存指定位置
  6. 关 MMU、清 Cache，跳转到内核入口
  │
  ▼
Linux 内核启动：自行开 MMU、建立虚拟内存映射、开中断
```

## 附：面试题——两个整数相加并打印结果

✅ 看似简单，但需要思考很多问题，例如：

1. **溢出问题**：`int` 加法可能超出范围（有符号溢出/无符号回绕）
2. 数据类型的位数与范围（int 通常是 32 位）
3. 输入合法性（scanf 是否成功读取）
4. 负数、打印格式（%d）等

示例代码（C 语言，含溢出检查）：

```c
#include <stdio.h>
#include <limits.h>  // INT_MAX / INT_MIN

int main(void) {
    int a, b;

    printf("请输入两个整数：");
    // 校验输入是否合法
    if (scanf("%d %d", &a, &b) != 2) {
        printf("输入格式错误！\n");
        return 1;
    }

    // 有符号溢出检查
    if ((b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b)) {
        printf("溢出！结果超出 int 范围\n");
        return 1;
    }

    printf("%d + %d = %d\n", a, b, a + b);
    return 0;
}
```

> 面试考察点：不是背代码，而是考察**边界情况意识**（溢出、输入校验、类型范围）和**工程习惯**。
