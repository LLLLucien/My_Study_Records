# 数据库TTL

## 回顾

- DDL：数据定义语言
  - 数据对象：数据库、表、视图、索引、函数
  - `CREATE`、`DROP`、`ALTER`、`TRUNCATE`、`GRANT`

- DML：数据操作语言，用于增删改查数据
  - 数据对象：表
  - `INSERT`、`DELETE`、`UPDATE`、`SELECT`
  - 表连接：
    - 内连接：`INNER JOIN`（交集）
    - 外连接：`LEFT/RIGHT OUTER JOIN`
      - 左外连接：`LEFT OUTER JOIN`
      - 右外连接：`RIGHT OUTER JOIN`
      - 全外连接：`FULL OUTER JOIN`（MySQL 不支持）（并集）
    - 并集：`UNION`
    - 交集：`INNER JOIN`
    - 差集：`LEFT JOIN`/`RIGHT JOIN`

  - **重点**

  ```sql
    SELECT
        c1, c2, c3, c4, c5
    FROM
        t1
    INNER JOIN -- 连接其他表（INNER JOIN 取交集，LEFT/RIGHT OUTER JOIN 取左/右表全部）
        t2
     ON
        t1.id = t2.id
      WHERE  -- 过滤原始数据
        c1 > 100 AND c1 < 200
    GROUP BY
         c1
    HAVING  -- 过滤分组后的数据
        c4 > 100
     ORDER BY -- 排序
        id DESC
     LIMIT -- 限制返回行数
      10;

  ```

## 事务处理

- 事务：一个或多个 SQL 语句组成的执行单元，要么全部执行，要么全部不执行
  - ACID：原子性、一致性、隔离性、持久性
  - 原子性：要么全部执行，要么全部不执行，要么成功，要么回滚
  - 一致性：事务执行前后，数据必须保持合法状态，所有约束（外键、CHECK、唯一键等）不能被破坏
    - 通俗理解：就像转账，A 转 100 给 B，不管中间发生了什么，最终 A 扣了 100、B 加了 100，**总额不能变**。如果 A 扣了 100 但 B 没收到，数据就对不上了，这就是不一致。一致性约定了所有这类规则，事务前后数据都必须符合规则，不能出现中间破坏规则的状态
  - 隔离性：一个事务的执行不能被其他事务干扰，相互隔离；
    - 隔离级别：
      - 串行化
      - 可重复读
      - 读已提交
      - 读未提交
  - 持久性：一个事务一旦提交，它对数据库中数据的改变就应该是永久性的，事务结束，数据写入磁盘

## TCL

- `BEGIN` 开始事务,直到提交
- `COMMIT` 提交事务
- `ROLLBACK` 回滚事务

```sql
    begin;
    -- 在提交之前，其他客户端还查不到已经改变的信息
    update account set balance = balance - 5 where id = 1;
    update account set balance = balance + 5 where id = 2;
    insert into log (`from`,`to`,`amount`) values (1,2,5);
    commit;
    -- 提交之后，其他客户端才可以查到已经改变的信息
```

```sql
    begin;
    -- 在提交之前，其他客户端还查不到已经改变的信息
    update account set balance = balance - 5 where id = 1;
    update account set balance = balance + 5 where id = 2;
    insert into log (`from`,`to`,`amount`) values (1,2,5);
    -- 回滚后，数据库恢复到事务开始前的状态
    rollback;


    -- 得到上一个id的函数last_insert_id()
    select last_insert_id();

```

## 隔离级别

| 隔离级别 | 脏读   | 不可重复读 | 幻读   |
| -------- | ------ | ---------- | ------ |
| 读未提交 | 可能   | 可能       | 可能   |
| 读已提交 | 不可能 | 可能       | 可能   |
| 可重复读 | 不可能 | 不可能     | 可能   |
| 串行化   | 不可能 | 不可能     | 不可能 |

**脏读**：读到了别人还没有提交的数据。好比你在编辑文档还没保存，另一个人打开看到了你的草稿，结果你最后撤销了——他看到的就是脏数据。

**不可重复读**：同一个事务内，两次读同一条数据，结果不一样。比如你第一次查余额是 100，别人转走了 50 并提交，你第二次查变成了 50。两次读到的值不一样，强调的是**同一行数据被修改了**。

**幻读**：同一个事务内，两次条件相同的查询，返回的行数不一样。比如你第一次查「部门 id=1 的员工」有 3 人，别人又插入了 2 个部门 1 的员工并提交，你第二次查变成了 5 人。两次查到的行数不一样，强调的是**多了或少了行**（插入/删除），不是同一行被改。

| 概念       | 本质区别      | 关系到                   |
| ---------- | ------------- | ------------------------ |
| 脏读       | 读到没提交的  | 别人还在改，你就看到了   |
| 不可重复读 | 同一行值变了  | 别人 UPDATE 了           |
| 幻读       | 行数变多/变少 | 别人 INSERT 或 DELETE 了 |

## 索引

- 目标：加快查询速度，但是会降低插入/更新/删除速度，占用磁盘空间
- 具体实现：B+ 树，红黑树，哈希表
- 自动创建索引：主键列，外键列，唯一约束
- 手动创建索引：`CREATE INDEX 索引名 ON 表名 (字段名);`

> **索引怎么工作**：无索引时是全表扫描——MySQL 一行一行读，每行都检查是否符合条件，相当于一本书没有目录只能从头翻到尾。有索引时走 B+ 树——先快速定位 key 对应的叶子节点（存的是匹配行主键），再拿着主键直接取对应行，相当于书末索引告诉你「CHN → 第 3、17、89 页」，不用翻不相关的行。
