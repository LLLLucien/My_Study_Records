## 信号量

- 原子性的整数，进行PV操作

- sem_init(&sem, 0, 1)
- **参数**：
  - 1.信号量本身地址，
  - 2.是否是线程间还是进程间，0表示线程间（一个进程内），1表示进程间
  - 3.1表示初始值为1,可以设置为其他值，例如60
    - 如果是1就称为*二元信号量* ，0或1
    - 如果是其他值就称为计数信号量，可以是任意正整数

P：获得资源 sem_wait(&sem); - sem>0,获得资源,sem-- - sem=0,进入阻塞状态

V：释放资源 sem_post(&sem); - sem++

## 自旋锁

**自旋锁（Spin Lock）**：一种忙等的排他锁。线程获取锁失败后**原地循环检查（自旋）**，不会进入睡眠，直到锁被释放。

### 自旋锁 vs 互斥锁

| 特性       | 互斥锁（mutex）                 | 自旋锁（spin lock）                                |
| ---------- | ------------------------------- | -------------------------------------------------- |
| 未获得锁时 | 线程进入**阻塞/睡眠**，让出 CPU | 线程**原地空转轮询**，持续占着 CPU                 |
| CPU 占用   | 低                              | 高（空转期间一直跑）                               |
| 上下文切换 | 有（睡眠→唤醒）                 | 无                                                 |
| 适用核数   | 单核、多核都可以                | **只适用于多核**（单核上永远等不到释放）           |
| 临界区大小 | 适用于**临界区大**的场景        | 适用于**临界区极小**的场景（几行代码）             |
| 能否休眠   | 可以                            | **绝对不能**（持有自旋锁时休眠会导致其他线程死等） |

> **新手口诀**：自旋锁 = 门口等你，一直敲门不离开；互斥锁 = 拿号排队，轮到你才叫你。

### 为什么自旋锁不适合单核？

在单核 CPU 上，持有锁的线程和你自旋的线程共用同一个核。你一直在自旋占着 CPU，持有锁的线程根本没法被调度执行，也就没法释放锁。于是形成死循环。

多核环境下，两个线程在不同核上运行：线程 A 持锁在核 0 跑，线程 B 在核 1 自旋等待；线程 A 执行完释放锁，线程 B 立刻拿到——没有上下文切换开销，非常高效。

### 自旋锁使用场景

- **内核中断处理**：中断上下文不能睡眠，只能用自旋锁
- **临界区极短**：比如只操作一个变量的 ++，连上下文切换的时间都比执行代码长
- **锁竞争不激烈**：大多数时候能立刻拿到锁

### 关键注意点

- 持有自旋锁期间**禁止调用可能阻塞的函数**，否则其他 CPU 上的等待者会一直空转
- 大部分情况下**用户态用互斥锁就够了**，自旋锁主要用于内核或极致性能场景

### Linux 自旋锁 API（内核）

| 函数                    | 作用                           |
| ----------------------- | ------------------------------ |
| `spin_lock_init(&lock)` | 动态初始化自旋锁               |
| `spin_lock(&lock)`      | 获取自旋锁（忙等）             |
| `spin_trylock(&lock)`   | 尝试获取，失败立刻返回而非自旋 |
| `spin_unlock(&lock)`    | 释放自旋锁                     |

### pthread 用户态自旋锁

```c
#include <pthread.h>

pthread_spinlock_t lock;

// 初始化
pthread_spin_init(&lock, PTHREAD_PROCESS_PRIVATE);

// 加锁（忙等）
pthread_spin_lock(&lock);

// 临界区（尽量短小）
n++;

// 解锁
pthread_spin_unlock(&lock);

// 销毁
pthread_spin_destroy(&lock);
```

### volatile 与自旋锁

`volatile` 只防止编译器将变量缓存到寄存器，**不保证原子性，不能替代锁**。配合自旋锁使用时，确保拿到锁之后读到的是内存中的最新值：

```c
volatile int shared_data = 0;

pthread_spin_lock(&lock);
shared_data++;  // 从内存读，而非寄存器缓存
pthread_spin_unlock(&lock);
```

## 读写锁

**读写锁（rwlock）**：允许多个读者同时读，但写者独占。核心规则：**读共享，写排他，写优先**。

### 读写锁的三种状态

| 状态           | 描述                                   |
| -------------- | -------------------------------------- |
| 未加锁         | 读/写锁都没被获取                      |
| 读锁（共享锁） | 一个或多个线程持有读锁，互相不阻塞     |
| 写锁（排他锁） | 只有一个线程持有写锁，阻塞所有其他读写 |

### 基本规则

| 谁先持有 | 后来者能否读         | 后来者能否写         |
| -------- | -------------------- | -------------------- |
| 无人持有 | 能                   | 能                   |
| 已有读锁 | **能**（读读不互斥） | **不能**（读写互斥） |
| 已有写锁 | **不能**             | **不能**（写写互斥） |

### 为什么需要读写锁？

普通互斥锁对所有操作一视同仁：即使 100 个线程都只是 `printf` 读数据，同一时刻也只能有 1 个在跑。读写锁允许读者并发，在读多写少的场景下性能远超互斥锁。

> **典型场景**：缓存系统、配置表、数据库查询——读操作占 90%+，写操作极少。

### 写者饥饿问题

如果读者源源不断，写者可能永远等不到锁（**饥饿**）。部分实现支持写优先策略来解决。

Linux pthread 提供 `PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP` 属性，让后续的写者优先于后续的读者，避免饥饿。

### 读写锁 API

| 函数                                | 作用                                 |
| ----------------------------------- | ------------------------------------ |
| `pthread_rwlock_init(&lock, &attr)` | 初始化读写锁，attr 可传 NULL         |
| `pthread_rwlock_rdlock(&lock)`      | 获取**读锁**（共享锁）               |
| `pthread_rwlock_wrlock(&lock)`      | 获取**写锁**（排他锁）               |
| `pthread_rwlock_tryrdlock(&lock)`   | 尝试获取读锁，失败立即返回           |
| `pthread_rwlock_trywrlock(&lock)`   | 尝试获取写锁，失败立即返回           |
| `pthread_rwlock_unlock(&lock)`      | 释放锁（读锁或写锁，统一用这个函数） |
| `pthread_rwlock_destroy(&lock)`     | 销毁读写锁                           |

### 属性设置

```c
pthread_rwlockattr_t attr;
pthread_rwlockattr_init(&attr);

// 设置写优先，避免写者饥饿
pthread_rwlockattr_setkind_np(&attr,
    PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP);

pthread_rwlock_init(&lock, &attr);
```

## 读写锁

- 读共享，写排他

```c
#define _POSIX_C_SOURCE 200809L

#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int n = 0;
void *rd(void *arg)
{
    while (1)
    {
        pthread_rwlock_rdlock(&lock);
        printf("%ld 读取：%d\n", pthread_self(), n);
        sleep(1);
        pthread_rwlock_unlock(&lock);
    }
    return NULL;
}
void *wr(void *arg)
{
    while (1)
    {
        pthread_rwlock_wrlock(&lock);
        n++;
        printf("====写线程，写入:%d\n", n);
        pthread_rwlock_unlock(&lock);
        sleep(3);
    }
    return NULL;
}

int main()
{

    pthread_rwlockattr_t attr;
    pthread_rwlockattr_init(&attr);
    pthread_rwlockattr_setkind_np(&attr, PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP);

    // 两个参数，第一个是读写锁，第二个是初始化参数，可用是NULL
    // 而用这个属性attr可用避免写线程进入饥饿状态
    pthread_rwlock_init(&lock, &attr);

    pthread_t t1, t2, t3, t4;
    pthread_create(&t1, NULL, rd, NULL);
    pthread_create(&t2, NULL, rd, NULL);
    pthread_create(&t3, NULL, rd, NULL);
    pthread_create(&t4, NULL, wr, NULL);

    pthread_join(t4, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    pthread_join(t3, NULL);

    pthread_rwlock_destroy(&lock);
    pthread_rwlockattr_destroy(&attr);
    return 0;
}

```
